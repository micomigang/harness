# 2026-09-27 Seedance reference input reachability fix

## Problem
Preview task creation could fail with Ark `InvalidParameter` / `resource inaccessible` on `content[n].image_url.url`. The prior adapter preferred Seedream `remote_url` values for cross-provider references. Those URLs can be temporary, protected, expired, or otherwise unreachable from the Seedance service even though Harness can display the locally cached candidate image.

## Fix
- Prefer each locked reference item's `local_path` and inline the exact cached bytes as `data:image/...;base64,...` in Seedance `image_url.url`.
- Fall back to an HTTP(S) remote URL only when there is no local cached file.
- Keep shot-specific reference selection, combination-first ordering, and current candidate bindings unchanged.
- Enforce Ark's 30 MB per-image limit and a conservative 56 MB aggregate inline payload ceiling before task submission, producing a clear local error instead of an opaque provider failure.
- No visual asset, storyboard, dialogue, sound plan, or QA artifact is regenerated by this patch.

## Why
Ark's video generation API accepts either a public image URL or Base64 image data. Using Harness's cached production-truth image avoids cross-provider URL reachability/expiry issues and keeps the exact approved image as the input.
